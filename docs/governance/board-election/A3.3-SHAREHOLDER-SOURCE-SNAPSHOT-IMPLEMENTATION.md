## Delivered in this slice

1. Tenant/election-scoped source snapshot schema with immutable holder, holding, and source-ledger-entry manifests.
2. Append-only reconciliation history storing the observed source digest, result, actor, timestamp and reason.
3. Database UPDATE/DELETE guards for all five snapshot/reconciliation tables on MySQL, SQLite and PostgreSQL.
4. Separate Governance permissions:
   - `governance.election.register.view`
   - `governance.election.register.prepare`
   - `governance.election.register.reconcile`
   No role grants are added.
5. API routes for listing, capturing, viewing and independently reconciling technical source snapshots.
6. Capture requires an authorized election with verified election-authority evidence. The preparer cannot reconcile their own snapshot.
7. The source digest is deterministic across repeated captures; capture timestamp is stored separately. Reconciliation re-reads the same cutoff and database timezone.
8. Snapshot rows preserve current identity status as current-only and explicitly mark temporal identity history unresolved.
