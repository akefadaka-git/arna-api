## 3. Delivered P1.2 scope

The merged implementation provides:

- An additive `people` natural-person registry with an ARNA-issued, immutable public UUID and Amharic-first bilingual name components.
- A nullable unique current association to the canonical Core User model at `mases_core/src/Auth/Models/User.php`.
- Nullable, indexed person references for employee, shareholder, and governance membership records, without backfilling historical records.
- Explicit `person_tenant_accesses` grants, so a global person record is not automatically visible in every tenant.
- Person, tenant-access, employee-record, Core User, shareholder, and governance-membership model relationships.
- Transactional service operations for profile creation, account link/unlink, tenant access grant/revocation, and employee/shareholder/governance record link/unlink.
- Permission checks separating tenant-level People management from global account-linking and cross-tenant visibility grants.
- Audited identity mutations that fail closed if the required security event cannot be persisted.
- Explicit natural-person versus legal-entity shareholder protection and no automatic inheritance of tenant membership, role, permission, employment, ownership, or governance authority.
- Contract, API integration, schema, UUID immutability, mass-assignment, permission, and MySQL concurrency regressions.

## 5. Explicit exclusions

P1.2 did not perform data backfill, automatic person matching or merging, identity-claim/KYC collection, production database operations, or deployment. The public UUID is an identifier, not proof of legal identity, a login identifier, a credential, or an authorization grant.

The API clean-install workflow verified the migration count of 58 on the inspected main baseline. That count is an evidence point for this revision, not a permanent invariant to hard-code without reviewing future migration changes.
